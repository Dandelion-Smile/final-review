# PPT/PPTX 资料笔记：前三步可执行修改方案

日期：2026-11-15。状态：用户已确认；前三步已实现并完成隔离环境验收。实施结果见 [实现与验收记录](../material-text-images.md)。

本方案依据当前工作区代码，细化总方案的步骤 1—3：资料笔记及版本存储、纯文字加配图解析、截图与文字任务分离。方案编写时仅新增本文；后续经用户确认实施，日常数据库、实际配置与运行服务未切换。

## 1. 本阶段完成后的结果与边界

完成本阶段后，选用新策略的新上传 PPT/PPTX 将具有以下处理能力：

```text
上传 PPT/PPTX（PPT 先缓存转换为 PPTX）
    ↓
提取原生标题、正文、列表、教学备注、页码及结构
    ↓
一个事务保存：基础预览、原始页、初始资料笔记 V1、后续任务
    ↓
    ├─ 文字任务：可靠文字 → 现有正式索引发布 → 现有知识构建
    │           无可靠文字 → 正常完成、零分块、跳过知识构建
    └─ 图片任务：仅复杂目标页 → 必要时转换一次 PDF → 逐页截图
```

- 后端可以读取、保存和追踪笔记历史；两个客户端基于同一旧版本保存，只有一个成功，另一个收到冲突，不静默覆盖。
- 新解析策略没有 OCR、视觉理解、视觉复核调用；文字知识提取和向量服务仍会按现有逻辑调用。
- 图片与文字任务分别领取、续约、重试、完成；图片失败或缓慢不会阻止已提取文字建立索引和首次知识构建。
- 现有基础预览继续可用；新笔记结构、历史版本、图片清单通过接口验收。

**本阶段交付的是后端基础与首次上传处理链路，不包含总方案步骤 4 的独立阅读编辑页面，也不宣称已经完成保存后自动同步知识库。**

保存接口先在显式开启的测试环境验证。语义修改只保存新版本并返回 `pending_integration`，不自动触发索引或知识重建；格式修改返回 `unchanged`。接口明确返回 `latest_saved_revision_id` 和 `indexed_revision_id`，不能把“已保存”显示成“检索/知识已更新”。只有首次上传 V1 自动进入现有处理链路。完成后续步骤 5、6 的版本发布和旧证据失效前，不向日常使用开放文字编辑保存，不默认切换日常上传策略。

首次 V1 任务始终读取被绑定的不可变 V1，而不是最新编辑内容；测试中保存 V2 后，V1 的索引指针仍明确指向 V1。后续自动同步将使用独立文字代次和发布目标接入，不能仅重新执行现有追加证据算法。

## 3. 步骤一：增加资料笔记及版本存储

### 修改文件

- 新增 `db/migrations/018_material_notes.sql`。
- 新增 `src/final_review/material_notes.py`：节点校验、来源归属、初始文档生成、语义输入序列化与哈希。
- 修改 `postgres.py`、`schemas.py`、`api.py`，补齐数据库启动检查和删除清理。
- 修改 `tests/conftest.py` 的内存存储适配，并新增单元和真实数据库测试。

### 数据结构

| 表 | 必需内容 |
| --- | --- |
| `material_note_heads` | 用户/课程/资料唯一；最新保存版本、初始版本、已索引版本、知识版本预留指针；保存序号、文字代次与发布目标；创建/更新时间 |
| `material_note_revisions` | 不可变 revision ID、连续版本号、上一版本、结构 JSON、schema 版本、语义输入哈希、修改者及时间 |
| `material_note_save_requests` | 用户/资料/幂等键唯一；请求摘要、结果版本；支持重试返回原保存结果 |

来源节点至少包含稳定 `block_id`、类型、原页、原始块关联、内容来源、正文或子节点。图片节点只引用本资料页号；状态与资源地址通过独立图片清单读取，不写入每次笔记版本。

初始原生块 ID 按文件哈希、页码、shape 路径、段落位置确定性生成；教学备注独立编号；后续用户新增节点由服务端生成或验证唯一 ID。原始页结果是原文对照依据，编辑不得反写原始页。

新关系约束确保资料确实属于该用户和课程，版本/父版本/头指针不能跨资料。删除资料、课程或账号时沿用现有删除语义，清理新增记录与任务资源；软删除后所有新增接口立即不可访问。

### 保存事务

1. 校验账号、课程可写状态、资料归属和新策略资格，验证 JSON 节点白名单、层级、体积及资源归属。
2. 在同一资料头行锁下先查询幂等键；相同键和相同请求返回原结果，相同键不同请求返回 409。
3. 核对 `base_revision_id`；与最新保存版本不一致返回 409，附最新版本号，不写入或覆盖内容。
4. 服务端与父版本及原始页比对来源：改写原文标 `user_edit`，新增说明标 `user_added`；不能靠客户端声明成为原生或可靠文字。
5. 从白名单文字节点生成语义输入哈希，保留文字、顺序、来源与准入属性，排除格式、图片开关、图片状态和 URL。完全不变的保存直接返回原版本；仅格式变化生成新显示版本但不增加文字代次。
6. 插入不可变新版本及幂等记录，更新最新保存指针后提交。当前阶段不触发修改后的模型调用，明确返回同步未接入状态。

不信任客户端传入的 `searchable`、`native_checked`、原生来源或任意 HTML/URL。危险原生片段被直接编辑后，不自动升级为可靠证据；保留待补充属性，用户另加完整说明才成为用户文字输入。空文档允许保存。

### 接口

统一前缀：`/api/courses/{course_id}/documents/{document_id}`。

| 接口 | 结果 |
| --- | --- |
| `GET /reading-note` | 最新 JSON、保存/索引版本指针、同步状态；无需等待资料 ready |
| `PUT /reading-note` | `base_revision_id`、幂等键、JSON；返回保存版本和同步状态；冲突 409 |
| `GET /reading-note/revisions/{revision_id}` | 授权资料内的历史版本，不能跨用户或跨资料访问 |

验收：版本不可变；并发保存一成功一冲突；成功响应丢失后重试不重复建版本；伪造来源与跨课程访问被拒绝；空笔记正常；格式变化不产生模型任务。

## 4. 步骤二：新增纯文字＋配图解析策略

### 修改文件与策略选择

- 修改 `config.py`、上传创建路径（以实际调用链为准，当前主要在 `api.py`）和任务创建逻辑。
- 修改 `material_structure.py`，新增 `material_text_images.py`，复用 `material_hybrid.py` 的原生提取与转换/渲染基础函数。
- 修改 `material_jobs.py` 的策略分发，不改变旧 `hybrid-slides-v1` 任务行为。

新增配置 `MATERIAL_PPTX_PARSE_MODE=hybrid_visual|text_images`，默认保持当前行为。新上传时固化 `parse_strategy=text-images-v1` 到资料和任务，不在执行中重新读取全局开关决定路径。旧任务无新字段时走兼容分支。

### 提取和文字准入

新策略保留全部可提取原文供预览，分别产生 `searchable`、`exclusion_reasons`、`content_origin` 和页级 `needs_page_image`。不把旧 `route=visual` 直接解释成整页文字都不可用。

| 内容 | 处理 |
| --- | --- |
| 标题、顺序可靠的完整正文、列表、代码 | 保留原文与段落，检查异常字符、坐标和阅读顺序后可入索引 |
| 教学备注 | 单独节点、单独来源检查；正文不可靠不直接导致完整备注被丢弃 |
| 复杂页中的独立完整说明 | 仅在可证明与图形关系独立、顺序可靠时准入；其余保守排除 |
| 表格单元、流程节点、公式碎片、连接关系不明的文字 | 预览保留，默认不入索引；附排除原因，并安排整页配图 |
| 图片、系统页标题/占位提示、图片 alt 和 URL | 不作为知识文字 |

首次实现不使用“文字够长”作为独立可靠性的充分条件。对无法确定的形状关系保守排除，不承诺复杂页文字恢复率。

### 与现有索引、知识任务的最小接线

为验证“截图不阻塞检索和知识库”，本阶段必须做首次 V1 发布的最小适配：

1. 从 V1 白名单节点生成可靠文字 sections，带原页和块映射，不再对空 sections 使用 `located_sections` 兜底提取全部原生碎片。
2. 非空文字走现有 `KnowledgeBase.prepare(..., plain_text=True)` 和正式发布事务；复用现有知识提取、核验、去重与入库算法。
3. 发布元数据带 V1 的 revision、输入哈希和任务代次；chunk ID 固化策略与文字版本，防止后续版本碰撞；初始原生与备注来源保留可追踪映射。
4. 无可靠文字时发布零分块的正式状态、不可变版本和 `no_reliable_text` 结果；不调用向量服务，不入队知识构建，且现有手动知识重试/复用上传入口也不能把此状态重新入队。
5. 文本发布核对原文件哈希、任务策略、目标 revision/输入哈希、处理代次、资料未删除和当前有效租约；图片结果不参与文字发布条件。

这只接通首次上传 V1，不扩展到用户修改后发布、历史引用新展示或旧证据生命周期，后者仍属于步骤 5、6。

### 零视觉验收

测试将 `SlideInterpreter` 构造、视觉客户端和 OCR 入口全部替换为调用即报错的哨兵。纯文字、图文、表格、公式、纯截图样本均须完成新策略。

- 纯文字 PPTX 的 PDF 转换及页面渲染调用为零。
- 旧 `.ppt` 允许必要的 PPT→PPTX 转换；纯文字场景仍不转 PDF。
- 纯截图资料的预览、笔记和图片任务正常，零正文索引、知识正常跳过。
- 页码占位文字不能让纯截图资料被误判为有知识正文。

## 5. 步骤三：截图与文字处理真正分开

### 任务结构与原子交接

新增 `db/migrations/019_material_text_image_jobs.sql`，扩展 `material_jobs`：任务用途、来源哈希、固化策略、目标 revision/文字代次、目标页集合及内部去重键。新策略 preview、text、images 使用独立任务 ID，沿用已有三个执行池和额度，不增加并发配置上限。

上传幂等键仍属于上传请求；内部任务用独立去重键，不能复用相同上传幂等键而违反现有唯一索引。首次文字任务按资料、策略、revision/代次唯一；图片任务按资料、源哈希、策略、目标集合唯一。重试复用原任务，且不重复创建 V1。

预览完成时一个事务执行：校验预览租约 → 保存原始页 → 创建 V1 和头指针 → 更新基础预览 → 入队文字任务 → 有目标页时入队图片任务 → 完成预览任务。全部提交后两条队列均可领取，无需等待任何一方结束。

### 图片检查点与状态隔离

- 在页记录中独立更新 `image_status/cache_key/error` 等字段，不替换整个原始页 JSON。
- 图片 worker 按目标页过滤；无目标页直接记为 `not_required`，不创建转换任务。
- 同源转换缓存加并发保护和原子文件写入，避免重试或租约更替时重复转换、覆盖半成品；缓存身份包含所属资料、原文件、策略和渲染参数，不只检查文件是否存在。
- 每页完成立即提交检查点；重试只处理未完成目标页，部分失败保留已完成页。
- 图片写入前核对任务租约、源文件、策略和目标集合；过期 worker 不能发布检查点。数据库只保存受控资源身份，接口不暴露本地路径或租约。
- `claim/fail/retry/finish/expire` 的图片分支只改变图片字段，不能把 `parse_status` 改为 ready 或 failed。
- 文本 publish 在锁定最新资料记录后，仅合并文字拥有的字段；不覆盖图片状态、最新笔记指针或并发元数据。图片完成也不回写正文或笔记 JSON。
- 图片状态单独计算 `queued/running/partial/ready/failed/not_required`；现有兼容字段仅作为摘要，真实页面结果以独立清单为准。

### 图片接口

| 接口（沿用前述资料前缀） | 行为 |
| --- | --- |
| `GET /page-images` | 目标页、每页状态、受控资源地址、错误摘要；无需正式索引 ready |
| `GET /page-images/{page_number}` | 仅返回所属资料、当前源哈希和策略下已完成图片；未完成不伪造成功 |
| `POST /page-images/retry` | 幂等恢复失败/未完成目标页；不重新提取文字，不入队知识任务 |

旧 `pages/{page_number}` 接口继续服务旧策略；新策略使用独立接口，不借旧 ready 前提。图片路径只能由服务器从已验证身份推导，校验仍位于上传资源目录。

### 必须通过的并行验收

1. 人为阻塞文字任务，预览事务提交后图片任务仍可领取和完成；原页接口可访问，文字状态仍未就绪。
2. 人为阻塞图片渲染，文字仍可发布，可靠文字可检索，首次知识任务已入队。
3. 图片失败，文字索引和知识任务不回退；重试图片不增加向量或知识模型调用。
4. 文字和图片同时更新，两个执行顺序下图片状态、笔记 JSON 与索引指针都正确，不发生整体 JSON 覆盖。
5. 截图完成前通过测试保存笔记 V2，图片到达后 V2 JSON 和最新保存指针完全不变。真实光标和撤销历史验收留给步骤 4 的网页编辑器。
6. 只为目标页渲染；重复任务与重启复用已成功页；旧租约不能写回；五份资料并行时失败互不污染。

真实课件优先使用仓库现有固定对照样本与可定位的原文件；样本缺失则如实列为待验收，不以合成样本冒充。记录文件哈希、总页数、可靠/排除块、目标/已渲染页数、视觉与 OCR 调用数、向量/知识调用数以及预览/文字/图片耗时。不承诺未经测量的提速比例；纯文字和纯截图样本必须分别验证。

只对本次改动引起的失败负责修复，其他已有失败单列并说明与本次的关系；发现影响本阶段正确性的前置缺陷时一并修复并记录范围。

## 7. 交付时应向用户报告的实际结果

交付报告必须区分已实现、测试通过、真实样本已验证和仍待后续实施，至少包含：

1. 新增表、接口、策略和任务拆分的实际修改文件。
2. 并发保存冲突、保存幂等和历史读取的实测结果。
3. 三类样本（纯文字、混合、纯截图）的文字准入、渲染页数与零视觉/OCR证据。
4. 图片被阻塞/失败时，正文可读、文字可检索、知识任务能继续的测试证据。
5. 隔离库迁移与并发测试结果、旧策略回归、真实课件核对结果及尚未通过项。
6. 当前默认开关、日常服务未切换、网页编辑页未交付、编辑后自动知识同步尚未接入的明确说明。

完成这三步的预期价值是：有版本保护的资料笔记后端已经建立，新 PPT 的可靠文字不再等待整页截图或视觉服务；复杂页的原貌可独立补齐。完整网页编辑体验和编辑后的知识一致性，继续按总方案步骤 4—6 实施。
