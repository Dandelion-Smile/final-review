# 第四步：独立资料笔记阅读编辑页与新增上传启用方案

日期：2026-11-15。授权：用户要求先给出执行方案，再直接实施，并确保后续上传可直接呈现第四步效果；本轮不再等待二次确认。

状态：已实施并在本机启用；验收记录见 [第四步实现与本机启用](../material-note-reader-step4.md)。

## 目标与交付效果

新上传 PPT/PPTX 默认选择已实现的 `text-images-v1` 策略。单文件在“资料”页上传成功后直接打开 `#/courses/{course_id}/materials/{document_id}/note`，先显示提取进度，笔记就绪后展示连续文档；批量上传保留每份文件的“打开资料笔记”入口。其他上传入口的 PPT/PPTX 同样生成资料笔记，课程资料列表始终可进入；保留旧资料、旧片段引用和旧 URL。

页面提供标题/页码目录、阅读/编辑切换、标题/段落/列表/代码格式、撤销重做、备注、用户补充说明、显式保存、原文对照、原页展开及隐藏/恢复、原文件下载。

## 按顺序执行

1. **保护基线与运行状态**：备份本轮将修改的文件，记录现有服务与任务状态。保留工作区其他未提交修改。日常迁移前保存数据库备份；不重建历史课件。
2. **接口与路由契约**：笔记详情返回资料标题、文件名、编辑资格、原文版本、页目录和各阶段状态。保存响应返回服务端规范化版本，用于准确更新用户编辑/补充来源。路由优先识别末尾 `/note`，避免误当成 chunk 引用。
3. **前端编辑器**：采用同系列锁定版本的 Tiptap React、StarterKit、自定义来源块/备注/图片节点。保持现有来源 JSON 契约。正文采用白色阅读页，左侧为真实页码目录；配色沿用课程深蓝 `#123c5c`，正文 `#193650`，辅助字 `#657b8a`，边线 `#dce5eb`，备注浅蓝 `#eef5fa`，待核对提示 `#94632f`。标题使用现有宋体/Georgia，正文沿用微软雅黑/PingFang，代码使用等宽字体。标志性结构是正文旁的原页/来源窄标记，传达真实来源而非装饰。
4. **保存与图片隔离**：输入不发模型或保存请求；手动保存使用基础版本和固定幂等键。保存期间锁定本次编辑，避免服务器规范化回填覆盖新输入。冲突保留本地内容，允许查看最新版本、对照和在明确操作后用最新基础版本重存；不静默覆盖。后台轮询只更新状态及独立图片 Context，不用 `setContent` 回灌正文，不改变光标或撤销历史。图片显隐通过用户操作修改图片节点属性。
5. **入口与验收**：资料列表和基础预览新增“打开资料笔记”；单个新 PPT 上传直接跳转。验证实际 React 19 构建、旧路由、正常保存、格式变化、备注与图片操作、图片晚到不丢输入/光标/撤销、多标签冲突、离开提醒、窄屏。真实 PostgreSQL 测试继续只使用隔离库。
6. **本机实际启用**：专项验证通过后，对本机日常数据库应用尚未应用的 018/019 迁移，设置实际 `.env` 的 `MATERIAL_PPTX_PARSE_MODE=text_images`、`MATERIAL_NOTE_EDIT_ENABLED=true`，重载本机 API 与资料/知识 worker，构建或确认当前前端热更新。检查重复旧 worker 和在途任务，避免中途使用错误代码。通过浏览器上传新课件验证从上传到资料笔记的真实链路，再报告访问地址与结果。远端不发布。

## 必须明确的范围

- 首期“文件”指原方案覆盖的 PPT/PPTX；PDF、Word、图片等格式保持原流程。
- 本轮开放笔记编辑保存，但不实现步骤 5—6 的自动索引更新和旧证据撤销。初始可靠文字继续索引和构建知识；编辑保存只产生笔记版本。
- 页面明确显示“资料笔记已保存；检索和知识库仍使用上传时文字，编辑同步待接入”，并分别展示保存、索引、知识版本，不显示虚假的“已同步”。纯格式变化不触发知识任务。
- 新流程仍为零视觉/OCR。原页图片加载失败可重试，不能阻塞阅读和保存。
- 自动进入页面无需等待截图、向量或知识构建。加载失败提供返回资料页与重试，不无限掩盖错误。
- 本轮不做云端协作、图片上传、模型润色、笔记导出或跨版本语义缓存。
