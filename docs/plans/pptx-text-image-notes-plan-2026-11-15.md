# PPTX 原生文字、原页配图与可编辑资料笔记：实施方案

日期：2026-11-15。状态：待用户确认。本文件仅为方案，未执行代码修改、依赖安装、迁移、服务重启或历史资料重建。

## 1. 本次交付范围

将新上传 PPT/PPTX 的资料处理改为：快速提取原生文字，生成独立的可浏览、可编辑资料笔记；复杂页面仅后台生成整页图片，不做 OCR、视觉理解或视觉复核；可靠文字继续进入现有知识库构建链路。

首期默认采用以下产品规则，用户确认本方案即按这些规则实施：

- 资料列表中的基础文字预览保留，新增“打开资料笔记”入口，跳转到独立页面。
- 资料笔记位于“资料”模块，是这份资料的可编辑阅读文档；与“笔记”模块中的 AI 生成笔记保持独立，避免来源互相引用形成循环。
- 初始按 PPT 标题和页码组织章节，不请求模型总结、改写或重新划分章节。
- 编辑器支持标题、段落、有序/无序列表、代码、教学备注和原页图片。整体为连续文档，不以知识卡片呈现。
- 首期采用显式“保存修改”：未保存的编辑不触发索引、模型或知识构建。离开未保存页面时提示。
- 复杂页使用整页截图，图片节点保留页码，可展开原页、隐藏或恢复；首期不做智能裁剪、图片上传或协作编辑。
- 保存后的文字版本供正式检索和知识构建；新增、修改内容明确标为用户编辑/补充，不伪装成 PPT 原文。
- 新流程先作用于新上传 PPT/PPTX。其他文件格式与已发布正式资料继续保持原处理方式；升级历史资料需另行操作。

## 2. 当前代码中可复用与必须改变的部分

| 当前能力 | 本次处理 |
| --- | --- |
| `material_structure.py` 原生提取、组合对象、段落/列表/坐标/备注 | 复用；将“是否调用视觉模型”改为“是否需要原页配图”，补充块级可检索标记 |
| `material_page_results` 页级结果及源文件/策略隔离 | 复用；原始提取与用户编辑分开，不用编辑内容覆盖原始页记录 |
| `material_hybrid.py` PDF 缓存、单页渲染 | 复用；新策略不调用 `SlideInterpreter`、OCR 或视觉核验 |
| `preview → parse → images` 单任务串行交接 | 改为预览后同时交接文字任务和独立图片任务，不能等文字索引完成才排截图 |
| `publish_material_job` 正式分块/版本/定位与知识任务的事务发布 | 扩展为指定笔记版本发布，增加最新版本检查和空文字发布分支 |
| `KnowledgeRepository.source/publish` 当前资料版本检查 | 保留并增加笔记保存版本和任务代次检查，拒绝过时构建结果 |
| 知识提取、证据支持性校验、内部去重、课程匹配算法 | 保留；通过输入适配继续使用 |
| 知识库当前追加/合并证据 | 增加证据失效和有效事实重算；当前代码没有自动撤销笔记删改前的证据 |
| `Materials.tsx` 基础/正式预览与引用定位 | 保留兼容入口，增加资料笔记页面和分开显示的状态 |
| 现有 Langfuse、资源额度、租约与重试 | 复用；增加新流程指标，校验视觉/OCR 调用为零 |

不能只把视觉开关关掉：当前混合链路遇到复杂页会因视觉服务未启用而失败，也不会自动创建可编辑文档。必须新增处理策略和任务交接。

## 3. 目标业务与任务流程

```text
上传 PPTX（旧 PPT 先转换为 PPTX，同源转换结果缓存）
    ↓
轻量提取：原生文字、标题、备注、段落、坐标、页码
    ↓
程序判断：哪些文字可独立使用、哪些块需核对、哪些页需要原页配图
    ↓
原子保存：基础预览 + 原始页结果 + 初始资料笔记版本 V1
    ↓
用户立即可打开资料笔记、阅读和编辑
    │
    ├─ 文字任务（绑定 V1）
    │    → 程序检查与确定性整理
    │    → 仅序列化可检索文字
    │    → 分块、向量化、原子发布正式文本版本与定位
    │    → 现有知识提取、证据校验、两级去重、入库
    │
    └─ 独立图片任务（绑定原文件哈希、策略和目标页集合）
         → 需要时转换一次 PDF
         → 只渲染需要配图的页
         → 更新图片清单与图片状态
         → 图片节点自行显示，保持用户正文和当前光标

用户保存修改 → 创建不可变笔记版本 V2 → 入队 V2 文字任务
             → 检索/知识状态显示更新中 → 新版本检查通过后发布
```

文字、图片和知识库各自有状态、检查点和重试预算。图片生成失败不回退文字版本；知识库失败不影响笔记阅读、编辑或已完成的文本检索。

纯文字 PPT 不启动 PDF 转换和图片渲染。纯截图 PPT 生成可阅读的图片笔记，文字索引为空，知识状态为“暂无可用于知识提取的文字”，属于正常结果。

## 4. 文字准入与来源规则

所有原生文字都可在基础预览中查阅，但只有来源和顺序可靠的文字进入检索/知识库：

| 内容 | 笔记显示 | 自动检索/知识提取 |
| --- | --- | --- |
| 普通标题、完整正文、列表、代码 | 保留原意、否定、条件和数值，可编辑 | 程序检查通过后允许 |
| 可完整提取的教学备注 | 单独保存、可展开并编辑 | 按教学备注来源独立检查和使用 |
| 复杂页中可独立识别、顺序可靠的说明正文 | 正文与配图一同显示 | 块级规则确认可靠时允许 |
| 流程图节点、表格格子、上下标公式、顺序不明或异常文字 | 标为原生片段/待补充，保留原页配图 | 默认排除，不把标签拼接成完整结论 |
| 图片及系统生成的图片标题、链接、占位符 | 作为原页图片节点 | 排除，不做 OCR、不向模型传图片 |
| 用户另行补写的说明 | 标为用户补充 | 作为用户文字进入现有证据校验流程 |
| 用户修改原正文 | 标为用户编辑，保留原文对照 | 以修改后的文字版本为证据，原页只作来源上下文 |

块级规则不能确定时采取保守处理，说明原因，不自动升级为“提取完整”。首期不承诺从复杂结构中恢复所有可靠正文；可用“补充说明”新增完整用户文字。

`content_origin` 使用 `native`、`teaching_note`、`user_edit`、`user_added` 等明确类型；原始可检索标记和来源由服务器计算，不能信任客户端传入的“原文/已核验”标记。原图不标为“视觉核验通过”。

正式检索文本从白名单结构节点生成，不能直接将富文本 HTML、图片 alt、图片 URL 或整个编辑器 JSON 送给知识模型。当前 `plain_material_text` 会把 Markdown 图片 alt 转成文字，不能直接复用该行为作为新笔记的入库转换器。

## 5. 编辑器与页面交互

拟新增 `MaterialNoteReader.tsx` 与样式文件，并在 `main.tsx` / `course-routes.ts` 中增加专用路由：

```text
#/courses/{course_id}/materials/{document_id}/note
```

该路由优先于现有资料片段引用路由解析，保持历史 `#materials/...` 和现有课程来源链接可用。

采用 Tiptap React 基础编辑器、StarterKit 和自定义来源/原页图片节点，使用结构化 JSON 保存，不引入协作云服务。选用其 React 集成和 React NodeView 机制，依据官方文档：[React 安装](https://tiptap.dev/docs/editor/getting-started/install/react)、[React NodeViews](https://tiptap.dev/docs/editor/extensions/custom-extensions/node-views/react)。实施时先验证当前 React 19、Vite 与扩展兼容性，并锁定同一系列依赖版本。

页面约定：

- 左侧目录按标题/页码跳转，右侧为连续正文；支持阅读/编辑、保存、撤销/重做、查看原文与下载原文件。
- 备注独立显示；原页节点显示“生成中 / 已就绪 / 失败可重试”，图片就绪后懒加载。
- 图片完成只更新独立图片清单，不能重新 `setContent` 替换编辑器正文，避免覆盖未保存内容、移动光标或重置撤销历史。
- 用户隐藏的图片不因后台完成而重新出现；隐藏/恢复只影响显示，不重新调用知识模型。
- 多标签页编辑使用版本冲突检查：保存携带 `base_revision_id`，冲突返回 409，保留本地内容并提示对比最新版本，不能最后写入者静默覆盖。
- 保存不等待向量或模型请求；显示“已保存 / 检索更新中 / 知识库更新中”，明确当前检索和知识库各自基于哪个版本。
- 首期不提供自动云端保存、智能排版、模型润色、图片识别、图片上传、多人协作或独立笔记导出，避免扩大本轮实现范围。

## 7. 并发、正式发布与知识版本同步

### 7.1 并行执行与版本保护

预览交接事务同时保存初始笔记并生成文字任务和独立图片任务。复用当前资料任务表和 `preview / parse / images` 三类执行池，不先提高转换、向量或模型并发。

保存版本与文字处理代次分开：纯格式变更只增加笔记版本；文字输入、顺序、来源或准入状态变化才增加文字代次。后台提交核对最新文字代次、输入哈希和对应正式版本，不能因一次纯格式保存就误杀正在运行的相同文字任务。文字相同的显示版本可沿用已有正式文本映射，页面按文字代次判断是否需要更新。

- `parse` 负责指定笔记版本的文字索引。图片任务只绑定原文件与目标页，不把资料标为文字已完成，也不等待文字发布。
- 版本保存、任务交接、页结果写入、索引发布均检查代次和租约；`parse_status` 兼容状态不能由图片 worker 回写成 `ready`。
- 用户连续保存 V2、V3 时合并尚未开始的更新，仅处理最新目标；正在运行的旧任务在检查点退出，不继续发起下一批模型请求，也不能提交结果。
- 新文本尚未发布前保留上一个正式索引，页面明确标示其版本；新文本与分块、定位、版本指针和知识任务在事务中统一发布。
- 仅格式、图片状态或图片显示变更不触发知识构建；文字输入、顺序、来源、准入状态变化才生成新的索引输入哈希。
- 空文字新版本也必须发布，并撤销这份资料旧版本的当前知识支持，不能因为没有新候选而跳过清理。

### 7.2 旧证据退出当前知识库

这是编辑功能的必需部分，单独实现与验收，不能只增加一个“重新构建”按钮。

1. 新文字正式发布时，将这份资料上一正式版本的证据标为已被替代，保留历史记录。
2. 重新计算受影响事实是否还有当前版本或其他资料提供的、核验通过的有效证据。
3. 没有有效支持的事实退出当前可用集合；没有有效事实的知识点退出当前可用集合。
4. 其他资料仍支持的共同知识保留，并更新其有效来源；受影响知识点的摘要/匹配数据应以剩余有效事实为依据，不能残留已删除断言。
5. 知识点列表、详情、目录树、去重快照与下游生成统一使用有效证据规则；相关缓存一并失效。
6. 新知识任务继续复用现有提取、支持性校验、两级去重与合并算法，再发布新版本的支持关系。

上述生命周期切换使用当前课程锁/事务和最新版本检查，避免并发构建重新激活旧证据。新知识构建失败时，显示同步失败并保留笔记和索引；不得为了显示旧知识而把已撤销证据重新设为有效。

已生成的正式笔记、题目和历史引用继续指向原不可变版本；来源接口可按已授权历史版本读取，不把旧引用的 chunk ID 对应内容替换为新正文。新增或调整 RAG 证据字段时，显示用户编辑/补充来源，防止将其标成老师 PPT 的逐字结论。

### 7.3 控制编辑后的模型消耗

先以资料版本为发布单位保证正确，再复用未改变的语义块结果：

- 缓存输入包括语义块全文及上下文、来源属性、稳定块映射、提取/核验策略和模型配置；输入不完全一致时不复用。
- 跨版本复用时重新绑定新 locator，并程序核对逐字 quote；不能把旧版本的证据 ID 直接复制到新版本。
- 复用提取、已通过的语义核验及向量结果；变化后的块继续执行完整流程。旧任务中失败/未核验的结果不当作通过缓存。
- 第一轮先保证正确性和断点重试；跨版本复用列为本轮独立步骤与测试项，不宣称现有同任务缓存已经具备此能力。

## 8. 按顺序实施与验收

| 步骤 | 主要工作/文件 | 完成标准 |
| --- | --- | --- |
| 1 | 新迁移、版本契约、`schemas.py`、新的 `material_notes.py` | 笔记版本不可变，保存冲突/幂等/用户隔离和空笔记可验证 |
| 2 | `material_structure.py`、`material_hybrid.py`、`material_jobs.py` | 新策略仅提取文字，复杂结构改为配图标记；视觉/OCR 客户端被禁止时所有新策略任务仍正常运行 |
| 3 | `postgres.py` 交接、`material_jobs.py` 图片任务、图片接口 | 文字与截图真正并行；只截目标页；截图失败不改变正文和文字索引 |
| 4 | `api.py`、独立资料笔记页面、路由、编辑器与依赖锁文件 | 基础预览可跳转；连续阅读/编辑/保存；图片到达不覆盖未保存编辑；冲突不丢内容 |
| 5 | `rag.py`、版本/定位发布、来源展示适配 | 只索引合格文字；保存异步更新，旧任务拒绝发布，旧引用仍指向正确版本；纯图片为正常无文字状态 |
| 6 | `knowledge_store.py`、`knowledge_jobs.py`、`knowledge_routes.py`、`knowledge_tree.py` | 保留核心算法；删改撤销旧支持、多来源事实保留、新版本发布及失败状态正确 |
| 7 | 跨版本语义块结果缓存、Langfuse、回归与对照 | 相同输入可复用且引用已重绑；无效/过期结果不复用；相同文件给出真实耗时和调用数量 |
| 8 | 文档、依赖与迁移检查、本机验收 | 检查通过后更新本机运行环境并报告实测结果；远端发布另行授权 |

其中步骤 6 完成前，不把“可编辑并自动同步知识库”作为交付完成；步骤 2–3 只能证明取消视觉路径，不能替代版本同步验收。

## 9. 测试清单

| 场景 | 必须证明的行为 |
| --- | --- |
| 纯文字 PPT、组合文字、备注、代码/数值/否定 | 原文完整、顺序正确；不用 PDF/OCR/视觉；可阅读、可编辑并完成索引 |
| 混合图文、图表、SmartArt、公式、表格和未知对象 | 原页配图准确；零视觉请求、零 OCR；危险结构片段不被拼成事实 |
| 纯截图 PPT | 图片笔记正常可用，索引为空、知识正常跳过；用户补写后可构建 |
| 五文件并行及其中一个失败 | 预览/笔记不等待正式槽位；各资料和各任务状态互相隔离 |
| 图片延迟、失败重试、隐藏后图片完成 | 不覆盖正文/光标/撤销历史；隐藏状态保留；已完成页复用 |
| 未保存、重复保存、只改格式、连续保存、多标签冲突 | 无未保存模型请求；保存幂等；无关变化不重建；最新版本胜出且不丢本地内容 |
| 索引或知识任务运行时再次编辑、进程重启、旧租约回写 | 旧结果无法发布；可复用完成检查点；最新版本正确完成 |
| 用户编辑原文与新增说明 | 引用匹配保存版本，来源显示用户编辑/补充，不能伪标 PPT 原文 |
| 删除事实、改写结论、清空正文 | 原旧支持退出当前知识库；没有新候选也完成撤销 |
| 同一事实被两份资料支持 | 修改其中一份只撤销该来源；仍有效的另一来源保留 |
| 新知识构建失败 | 笔记与索引仍可用；被撤销的旧结论不重新参与新生成 |
| 历史资料、旧笔记/题目引用、旧 URL | 不强制重建，历史来源内容与版本保持正确 |
| 跨用户/课程/文件/策略/模型缓存与资源访问 | 无越权、串缓存或任意资源加载 |

测试分层：单元测试、独立 PostgreSQL 迁移/事务/并发测试、网页端测试、固定真实课件对照。新链路测试将 `SlideInterpreter`、视觉请求、OCR 入口替换为调用即失败的哨兵，防止“关闭一次开关但仍有旁路调用”。

Langfuse 继续使用现有项目和资料级关联，增加 `parse_mode=text-images-v1`、笔记版本、任务用途以及：

- 笔记可阅读耗时、文字可检索耗时、图片完成耗时、知识完成耗时。
- 原生文字/排除块/用户编辑块数量、渲染页数、缓存命中、被替代任务数量。
- 视觉请求数与 OCR 调用数均为 0；向量和知识模型用量单独统计。
- 排队、转换、渲染、额度等待、提取、核验与两级去重的耗时、请求和实际 token。

对照使用同一批文件，区分冷/热缓存和图片生成耗时；不承诺未测量的提速比例。目标是新资料笔记不慢于当前轻量预览，正式文字不再等待 PDF、截图或视觉服务。知识库仍会使用大模型。

## 10. 启用、兼容与回退

拟新增独立配置 `MATERIAL_PPTX_PARSE_MODE=text_images`，为新上传固化 `text-images-v1` 策略。保留当前 `hybrid_visual` 策略供原任务完成及必要回退；新策略内部没有视觉失败后的自动回退路径。

执行前保存相关文件基线并保留现有未提交改动；依赖和迁移通过测试后先在本机验证。启用后先用合成样本与固定真实课件验收，再用于新增上传。旧任务按入队时固化策略完成，不能在处理中途静默切换模式。

回退默认策略只影响新上传，不删除已经保存的资料笔记、版本、历史引用或配图。编辑过的资料继续按其保存版本处理；不能回退成原始 PPT 并丢失用户改动。

确认本方案后才开始步骤 1。本轮仅新增此方案文档，未更改当前运行链路。
