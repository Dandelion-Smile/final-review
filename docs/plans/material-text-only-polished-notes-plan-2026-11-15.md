# 纯文本资料解析与大模型润色资料笔记：修改方案

日期：2026-11-15。状态：待确认，仅方案；本轮未修改业务代码、数据库、配置或运行服务。

本方案替代原方案中“复杂页插入整页截图”和“初始笔记不经模型改写”的要求。保留已经完成的独立阅读编辑页、版本保存、冲突保护和原文追溯。

## 1. 目标结果

```text
上传资料
    ↓
只提取原生文字、标题、列表、备注及可确定的表格结构
    ↓
保存不可变原文快照与稳定来源块
    ├─ 可靠原文 → 正式文字索引 → 现有知识提取、核验、去重与入库
    └─ 全文文字输入 → 文本大模型组织标题、章节与段落
                     → 忠实性及覆盖检查
                     → 连续、可阅读、可编辑的资料笔记
```

新资料笔记不包含系统截图、原页图片节点或图片占位框，不调用视觉理解、视觉复核或 OCR。PPT 不为解析而转换 PDF，也不启动页面渲染。必要的旧 PPT→PPTX、DOC→DOCX 格式转换可以保留。

这里的“统一纯文本”建议覆盖新增 PPT/PPTX、文字型 PDF、Word、MD/TXT。纯图片、扫描 PDF 和纯截图 PPT 若没有原生文字，保留原文件并明确提示“没有可提取文字”，不通过 OCR 或模型想象生成正文；允许用户手动补充文字。历史正式资料不批量重建。

## 2. 润色的具体要求

### 2.1 生成完整阅读文档，不生成摘要卡片

- 根据全文内容组织标题、一级/二级章节、正文、列表和必要代码块；相邻页面属于同一主题时可以合并。
- 不机械地每页生成一章，不机械地每个文本框生成一段，不重复显示“第 N 页 / 课件原文 / 原生片段”。
- 合并重复标题、页眉页脚和重复表述，但保留新增信息、条件、例外、否定、数值、命令、参数及示例。
- 教学备注纳入对应章节；需要区分授课提示时保留“教学备注”，不把它改写为未经说明的正文结论。
- 本轮是忠实整理，不扩展课外知识，不增加考试重点、考频、练习题或原文没有的推导。
- 内容覆盖整个可用资料，不只整理检索 top-k 片段，也不使用压缩摘要替代原文事实。

模型输出结构化结果，由服务端转换为现有编辑器 JSON；不接受任意 HTML、图片 URL 或模型自造的来源标记。

### 2.2 模型必须保留来源边界

每个正文段落和列表项关联一个或多个真实原文块 ID，标题可关联其覆盖的章节范围。页码从这些块由服务器计算，模型不能自造页码或引用。

- 原文保留 `native` / `teaching_note` 等来源。
- 模型整理的正文标为 `model_polished`，界面按整份笔记标示“根据课件文字整理”，不标为老师逐字原文。
- 用户改写、用户补充继续由服务器标为用户内容，不能通过客户端字段伪装成原文。
- 一个段落可跨多页，需扩展现有单页定位契约；来源可在章节或段落操作中展开查看，默认不反复占据正文空间。

### 2.3 复杂内容的处理

| 原文情况 | 处理方式 |
| --- | --- |
| 完整标题、段落、列表 | 保留顺序和上下文后交给文本模型整理 |
| 原生表格 | 保留表头、行列、单元格及合并关系；关系明确时可转为可读列表或说明段落，不先压平成无关联词串 |
| 多文本框组成的双栏或对照表 | 改掉“只要纵向重叠就整页不可靠”的规则；只有能确定行列对应时才按对应关系组织 |
| 图形里的独立完整说明 | 逐块判断可用性，不因同页其他对象复杂而整体排除，也不只凭字数判定可靠 |
| 缺少箭头、顺序、条件的流程节点 | 不猜流程、因果或先后；必要文字收在该章节的“原文补充”，附一句关系未恢复说明 |
| 不完整公式、乱码、无法确定的碎片 | 不擅自修正或补全；简短说明，原始提取文本仍可在原文对照中查阅 |
| 纯图片页、无原生文字页 | 不生成截图、不 OCR；不向文本模型发送空输入，也不生成虚构内容 |

“原生片段·待补充”不再逐块显示在主文档里。少量未恢复内容集中说明，不能让大量无上下文片段再次充满阅读页。

## 3. 原文、笔记与知识库的关系

本轮建议采用：**润色笔记负责阅读，可靠原文负责检索与知识证据。**

当前代码从 `revision.body` 生成索引输入。如果直接将初始正文替换成模型改写结果，模型改写就会被当成原始证据，因此必须同时改变这个接线，不能只在前端加一次模型调用。

- 新增不可变原文快照，保留原文结构、稳定块 ID、原始文本、页码、可靠性和策略版本。
- 索引/知识任务绑定原文快照，继续复用现有知识核心算法，不从润色笔记反向提取原始证据。
- 润色任务绑定同一原文快照和生成配置。模型失败不回退已经完成的原文索引，也不阻塞知识任务。
- 原文版本与笔记版本分别展示，例如“笔记 V2 / 检索：原文 T1 / 知识：原文 T1”，避免 V1 同时指原文和润色笔记。
- 手动编辑保存仍只保存笔记，不自动重新润色、不自动重建知识库。编辑影响正式检索/知识仍需后续版本同步和旧证据失效，不能借本轮润色绕过这一要求。

对已有资料执行“基于原文重新生成纯文字笔记”时，仅生成新的阅读版本，不自动替换其已发布的正式索引或知识支持关系。原文提取规则改变后的索引升级需单独绑定正式版本和证据生命周期，防止已有旧证据残留。

## 4. 长文档生成与质量检查

采用“全文目录规划 → 按主题分批整理 → 程序合并”的过程，避免把整份几十页课件塞进一个不受限请求，也避免分批后重复标题、丢内容或章节互不衔接。

1. **输入准备**：从完整原生块构造输入，带页码、原始标题、块类型及可靠性。若复用既有检索 chunks，必须依据真实来源偏移消除 overlap，不能把重复分块再次当作新内容。
2. **目录规划**：文本模型依据全文标题、块清单与必要上下文规划章节，并分配原文块。这里只组织资料，不把标题清单当成已经完成的正文。
3. **分批整理**：每批读取所属章节的完整原文块及必要边界上下文，输出标题、段落、列表、代码和来源映射；不是对各页各自压缩摘要。
4. **覆盖检查**：每个有效原文块必须记录为保留、合并、附录或有明确原因的排除。标题页和重复页眉可以排除，不能静默漏掉独立教学内容。
5. **忠实性检查**：检查来源 ID、数值、否定、条件、代码、命令和参数。正文改写还需文本层面的支持性复核；引用合法不等于含义正确。
6. **有限修复**：复核失败只修复受影响批次。将 SDK 重试、结构化响应重试与修复合并计入总预算；不让多层重试相乘。截断时拆分受影响批次，不发布被截断正文。
7. **原子发布**：整份笔记结构与覆盖检查通过后再发布，部分章节保留检查点但不冒充完整笔记。

程序规则与模型复核不能保证绝对零误差；验收仍需对照真实课件检查遗漏和错误关系。失败批次不当作通过结果复用。

## 5. 页面与任务交互

新上传流程的状态分开显示：提取原文 → 正在组织章节 → 正在整理正文（已完成 X/Y 批）→ 正在校验 → 笔记可编辑。原文索引和知识状态独立展示。

- 原生提取完成后可立即查看只读原文；最终润色笔记需要等待文本模型完成，不承诺与原轻量预览相同的就绪速度。
- 首次新笔记校验完成后作为第一版可编辑笔记打开，沿用现有独立路由、工具栏、保存和冲突保护。
- 模型失败时给出失败原因及重试入口；可以明确选择“使用原文开始编辑”，不能把原文回退伪标为润色完成。
- 用户已开始编辑原文回退稿或已有笔记时，晚到的润色结果只保存为候选，不覆盖正文、未保存内容、光标或撤销历史；应用候选需用户明确操作并再次校验基础版本。
- 保存后的普通修改不自动调用模型。需要重新生成时使用明确的“基于原文重新生成”动作，不通过输入、页面轮询或图片状态变化触发。
- 新策略页面取消图片状态、图片轮询、截图重试入口和页图片占位框；目录按章节标题组织，原页定位移到来源查看中。

## 6. 代码与数据改造

建议新策略标识为 `text-polish-v1`，与当前 `text-images-v1` 隔离。旧策略代码和不可变历史保留；新策略不以关闭视觉开关后落入旧转换函数的方式实现。

| 位置 | 修改内容 |
| --- | --- |
| `config.py`、上传创建入口 | 新增统一资料模式 `MATERIAL_PARSE_MODE=text_only_polished`；按上传时固化策略路由所有新增格式，避免只有 PPT 改了、图片入口仍自动 OCR |
| `material_structure.py`、`material_conversion.py` | 原生文字适配、表格结构、块级可靠性；新路径完全绕开视觉/OCR/截图回退 |
| 新 `material_text_source.py` | 统一原文快照、来源块、输入白名单、结构序列化及确定性去重 |
| 新 `material_note_polish.py` | 独立润色输入/输出契约、目录规划、分批生成、覆盖与忠实性检查、编辑器文档转换 |
| 新 `material_note_polish_jobs.py` | 独立持久队列、租约、检查点、批次重试、候选结果和发布栅栏，不占用提取队列等待模型 |
| `llm.py`、模型配置 | 复用文本模型客户端和鉴权，增加独立润色模型、超时、输出预算；不复用现有“笔记”模块的多资料选取/生成会话，也不使用视觉模型配置 |
| `material_note_store.py`、`postgres.py`、`material_jobs.py` | 原文发布与润色生成分开入队；从原文快照建立索引；无图片任务；发布检查源哈希、快照、任务代次和用户编辑版本 |
| `material_notes.py`、`schemas.py`、`material_note_routes.py` | 接纳受控的模型整理来源、多个原文块/页的映射、候选版本与生成状态；客户端仍无权伪造来源 |
| `MaterialNoteReader.tsx`、编辑器节点、目录与资料入口 | 连续润色正文、章节目录、统一来源提示、无图片布局、生成进度、重试和候选应用 |
| 新迁移（当前 019 之后，执行前核对序号） | 原文快照与块、润色任务/批次结果/来源映射；头指针与版本类型扩展，按用户/课程/资料约束并覆盖删除清理 |

当前 `material_jobs` 的图片阶段不能直接改名承担润色：旧任务语义、重试预算及已有图片记录需要保持可区分。润色使用独立队列和独立状态，首期先限并发，不扩大当前模型全局额度。

## 7. 模型消耗与可观测性

- 复用当前文本模型提供商与鉴权，独立配置 `MATERIAL_NOTE_POLISH_MODEL_ID`；不自动选择 `MATERIAL_VISION_MODEL_ID`。
- 对相同用户/资料、完整输入及上下文、原文快照、提示词/结构版本、模型和参数生成缓存键；完全一致才复用。
- 已通过的批次结果可在同任务重试时复用；失败、未核验和过时结果不作为通过缓存。不能只凭某段文字相同跨不同上下文复用。
- Langfuse 记录原文提取、目录规划、各批润色、复核、修复、发布的耗时、请求数及实际输入/输出 token；视觉、OCR、截图和 PDF 渲染调用数必须为 0。
- 润色与知识构建的模型消耗分别统计，不把“取消视觉模型”描述为“不再调用大模型”。真实耗时与费用以测试结果报告，不预先承诺节省比例。

## 8. 历史资料与本机切换

- 新增资料默认走新策略；现有资料保留原文、旧笔记版本和历史引用，不自动删除截图文件或覆盖用户编辑。
- 已有资料新增“基于原文生成纯文字笔记”入口，优先复用原生提取缓存；结构信息不足时只重新读取源文件文字，不重新 OCR 或截图。
- 当前两份 Docker 课件作为重点对照样本，先生成纯文字候选，验证连续性、覆盖和来源；应用候选后当前阅读版本不含图片，旧版本仍可审计。
- 切换前盘点旧视觉、OCR、截图任务。未开始的相关任务正常终止；运行中的任务在检查点停止继续发起调用，需要迁移到新流程的任务以新代次入队，不把正常替代记为资料损坏。
- 对已由其他旧策略完成的正式文字，不能因为生成新笔记就偷偷改写旧索引；否则会重新触发尚未补齐的旧证据失效问题。
- 测试通过、保存基线与数据库备份后，再更新本机配置、迁移和相关服务；远端发布不包含在此方案内。

## 9. 实施顺序与验收

| 步骤 | 修改内容 | 完成标准 |
| --- | --- | --- |
| 1 | 固化原文/润色/索引契约与新迁移 | 原文不可变；模型稿、用户编辑和原始证据不混用；权限、并发、删除可验证 |
| 2 | 全格式纯文字提取及来源结构 | 新链路视觉/OCR/截图/PPT 转 PDF 哨兵均零调用；表格行列和独立正文正确保留 |
| 3 | 文本模型润色与质量检查 | 具有标题层级和连续正文；全量来源覆盖可审计；无新增无依据结论 |
| 4 | 持久任务、缓存和发布保护 | 长课件分批不截断；中断可重试；旧任务和晚到结果不能覆盖用户编辑 |
| 5 | 前端纯文字阅读与生成状态 | 无截图及图片占位；无满屏“待补充”；章节目录、编辑、保存和来源对照可用 |
| 6 | 当前 Docker 资料与合成样本回归 | 检查对照表、流程标签、数字/否定/代码、纯截图页、重复标题和遗漏；纯文字候选不损坏旧版本 |
| 7 | 本机启用与实测报告 | 新上传直接走新策略；模型调用、token 和各阶段耗时可核对；编辑仍有准确版本提示 |

必须覆盖模型超时/截断/结构错误、重复点击生成、同文件重试、多文件并发、生成期间另页保存、纯图片无文字、原文与润色引用错配、跨用户访问及缓存隔离。
