# 第四步：资料笔记阅读编辑页与本机启用

日期：2026-11-15。已按 [执行方案](plans/material-note-reader-step4-plan-2026-11-15.md) 实施，用户授权包含本机启用；未发布远端。

## 现在上传会发生什么

在本机 [课程工作台](http://localhost:5173/#/courses) 的资料页上传一个新的 PPT/PPTX，会自动打开该资料的独立笔记页：

```text
#/courses/{course_id}/materials/{document_id}/note
```

先显示文字提取进度，原生文字和初始笔记就绪后即可阅读和编辑。原页截图、文字索引和知识构建在后台独立执行，不是打开笔记的前置条件。批量上传不强行跳转，每份上传结果和资料列表均有“打开资料笔记”链接；其他上传入口的 PPT/PPTX 同样生成笔记，可从资料列表进入。

仅覆盖后续新增且采用新策略的 PPT/PPTX。已有正式资料没有重建；非 PPT 文件沿用原来的预览和处理流程。

## 页面能力

- 左侧按原课件标题、页码定位，右侧连续正文；宽屏并排、窄屏目录置顶。
- 阅读/编辑切换；标题、段落、加粗、列表、代码；撤销、重做和新增补充说明。
- 教学备注独立显示，可展开、收起和编辑；原生片段保留待核对标记。
- 原页图片就绪后懒加载，可放大、隐藏和恢复，生成失败可重试；图片读取失败可重新加载。
- 查看上传时的不可变原文、下载原始文件。
- 显式“保存修改”和 Ctrl/Cmd+S；未保存离开提示；保存期间禁止重复编辑覆盖本次请求。
- 多标签页保存冲突保留当前内容，展示本地与最新版本对照；只有明确选择“放弃本地修改，载入最新”才替换正文，没有静默覆盖。
- 保存、检索、知识版本分别显示；后台使用轻量状态接口，不反复下载编辑器正文。

Tiptap `core/react/pm/starter-kit` 均锁定 3.34.0，React 19 构建和真实输入验证通过。依赖与 React NodeView 采用 [官方 React 集成](https://tiptap.dev/docs/editor/getting-started/install/react) 的方式；来源块和原页图片节点独立定义，富文本序列化过滤掉编辑器默认的额外属性。

## 图片与编辑隔离

图片清单通过独立 React Context 更新，原页节点自行刷新。后台图片完成和状态轮询均不调用 `setContent`，不替换文档、重置光标或清空撤销历史。

保存返回服务端规范化版本；界面仅用一个不计入撤销历史的事务更新来源属性，不用整篇正文回填。编辑器自身的默认属性（例如代码语言空值）不会混入服务端结构契约；图片 alt、URL、后台状态也不会写成笔记文字。

## 保存不等于知识同步

本轮为第四步，没有实施步骤 5—6 的编辑后索引更新和旧证据失效。

首次上传 V1 的可靠文字会正常索引、构建知识。编辑后保存为 V2、V3 时，保存的是资料笔记；检索和知识库仍指向 V1，接口返回 `pending_integration`。页面固定说明这一边界，不显示虚假的“知识已更新”。仅格式、图片显隐变化不生成新的语义输入或知识任务。

如需使编辑后的文字参与检索和知识提取，继续完成后续版本发布和旧证据失效机制，不能直接对本轮保存结果运行现有追加证据算法。

## 修改范围

新增前端：

- `MaterialNoteReader.tsx`：加载、连续阅读、工具栏、保存、冲突、原文对照、目录和版本状态。
- `material-note-editor.tsx`：来源/备注/片段/原页 NodeView、基础编辑扩展及对话框。
- `material-note-api.ts`：类型与服务端结构序列化。
- `material-note-reader.css`：响应式阅读工作区。

接入 `main.tsx`、`course-routes.ts`、`Materials.tsx`、`NoteMaterialPicker.tsx` 及资料入口样式。阅读页采用懒加载，旧引用 URL 和已有资料预览继续兼容。

后端扩展 `material_note_routes.py`、`material_note_store.py`、`api.py`：补充页面元信息、规范化保存版本、上传结果中的固化策略，以及无正文的 `GET .../reading-note/status`。没有新增数据库迁移，沿用前三步的 018/019。
