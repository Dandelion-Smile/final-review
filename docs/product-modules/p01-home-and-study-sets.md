# P01 主页与学习集：讨论记录与方案

日期：2026-10-24  
状态：讨论中；导航收起规则与主页学习集展示方式已由用户明确，其他建议仍待讨论。  
上级文档：[产品方案与模块规划](../product-design-v2-discussion.md)。

## 1. 用户本轮明确提出的要求

1. 初次登录后，未选择学习集时，主导航只显示“主页”“学习集”“日历”。
2. 只有选择当前学习集后，才显示这门课程对应的导航内容。课程内栏目沿用资料、笔记、测试、学习报告、与 AI 辅导聊天。
3. 主页主栏自上而下显示：AI 助手打招呼或激励学习的话、学习集总览、我的资料总览、我的笔记总览、我的测试总览。
4. 主页右侧显示日历和软件更新公告栏。
5. 顶部导航栏显示用户头像，点击后进入设置和个人中心。
6. 顶部导航栏还有学习计时器入口，点击可设置本次学习的倒计时。
7. 主页总览中的内容点击后，跳转到相应的新页面展示内容。
8. 已进入课程后，返回“主页”不收起课程导航；进入“学习集/我的学习集”列表才收起课程导航。
9. 主页学习集区突出最近使用的一个，旁边提供其他最近学习集和“查看全部”。

“新页面”建议理解为应用内独立页面，保留返回路径；是否有外部新标签页需求尚未提出。主导航只显示三个项目，不影响顶部工具入口的存在。

## 2. 主页布局建议

```text
顶部：品牌/页面信息                         学习计时器   用户头像
主导航         主栏                             右栏
主页           AI 问候 / 激励语                  小日历
学习集         学习集总览                       软件更新公告
日历           我的资料总览
               我的笔记总览
               我的测试总览
```

这是桌面端的信息布局示意，不是已确认的视觉稿；主导航的实际位置和样式待后续讨论。移动端建议单栏排列，并将右栏内容放到主栏之后，避免挤压资料和笔记。

### 2.1 各区域的建议内容

| 区域 | 建议展示 | 建议交互 |
| --- | --- | --- |
| AI 问候/激励语 | 一到两句问候，可结合昵称与真实的近期学习记录 | 是否可点击进入 AI 尚待讨论；默认不新增全局聊天入口 |
| 学习集 | 用户已明确：突出最近使用的一个，旁边显示其他最近学习集和查看全部；继续学习与新建按钮为建议 | 点学习集进入该课程；点查看全部进入学习集列表，并按规则收起课程导航 |
| 我的资料 | 所有学习集下最近上传的少量资料，标注所属学习集与处理状态 | 点资料看详情；点查看全部进入跨学习集资料列表 |
| 我的笔记 | 所有学习集下最近使用或更新的少量笔记，标注所属学习集与状态 | 点笔记进入阅读/编辑页；点查看全部进入跨学习集笔记列表 |
| 我的测试 | 所有学习集下少量测试，优先考虑未完成作答，标注所属学习集与状态 | 点测试按状态进入详情、继续作答或结果页；点查看全部进入跨学习集测试列表 |
| 日历 | 当前月份、今日与有安排日期的标记 | 点日期看当日安排；查看完整日历进入日历页 |
| 软件更新公告 | 少量最新公告的标题、日期和摘要 | 点公告进入站内详情，历史公告入口按需要提供 |

以上数量、排序和具体字段均为建议。总览应保留少量条目与“查看全部”，避免主页成为四份完整管理列表。公告需要有真实内容来源；首期如何维护另行明确，不据此增加完整运营后台。

用户已选择“突出最近使用的一个，同时提供其他最近学习集和查看全部”的呈现。展示多少其他学习集、按访问还是实际学习行为判定最近使用，仍待细化。建议将主页的最近学习集与当前课程导航分别表达：它们通常相同，但属于内容排序与导航状态两个不同概念；主页资料、笔记和测试的总览范围不随保留的课程导航自动改变。

### 2.2 AI 问候的边界

- 用户明确希望体现 AI 助手的陪伴感，问候以简短、自然为目标。
- 若提及“昨天学了多久”“还有几天考试”等信息，必须有相应真实记录。
- 问候区是否每天动态生成、是否出现助手形象，尚待设计；暂不扩展为新的交互功能。

## 3. 导航与跳转建议

### 3.1 全局与课程内导航

**用户已明确**：

- 未选择学习集时只显示三个全局导航；选择后显示相应课程导航。
- 返回主页保留已显示的课程导航。
- 进入学习集列表才收起课程导航；不再采用“回到任意全局页面就收起”的建议。

依此规则，日历等页面切换不应被额外设置为收起触发点。学习集列表中收起导航不等于删除最近学习记录；是否清除当前课程选择、刷新或重新登录后如何恢复，仍需细化。

**建议，待确认**：

- 全局的“主页 / 学习集 / 日历”一直可访问。
- 进入学习集后，在课程名称下显示该课程的五个入口，并有清晰的切换/返回入口。
- 当前主页面与课程导航展开状态分别表达：位于主页时高亮“主页”，课程名称及子导航保留，但不把课程子页面误标为当前页面。
- 从学习集列表回到主页时，沿用已收起状态，不因最近学习集卡片存在就自动重新展开；重新进入具体课程后再显示。
- 可记住上次学习位置用于“继续学习”，但不因此在从未选课的首次登录主页自动展开课程导航。
- 从全局总览进入某份资料、笔记或测试详情时，明确其课程归属，并展示对应课程导航；保留“返回主页/返回全局列表”的路径。

建议的跳转示例：当前展开课程 A → 返回主页，A 导航保留 → 打开课程 B 的笔记，切换为 B 导航 → 返回主页，B 导航保留 → 进入学习集列表，课程导航收起。跨课程内容点击时切换导航的细节尚待确认。

### 3.2 跨学习集列表

主页的资料、笔记、测试被用户描述为总览，因此建议支持跨学习集查看；此为解释与设计建议，尚未确认。

- “查看全部”分别打开全局资料、笔记和测试列表，可按学习集筛选。
- 这些页面通过主页入口访问，不额外增加三个全局主导航项。
- 课程内的资料、笔记、测试页面则固定为该学习集范围。
- 点具体条目进入同一份内容详情，不因入口不同复制资料或笔记。

### 3.3 点击测试的规则

点击主页测试条目建议先按状态区分：有未完成作答时继续该次作答；已完成的结果记录进入结果页；尚未开始或仍是草稿的测试进入详情。不能仅因点击一个总览条目就不经提示地启动新的计时考试。

## 4. 学习计时器建议

用户已明确需要“设置学习时长的倒计时”。

建议第一版支持：选择预设时长或自定义分钟数、开始、暂停/继续、结束、到时提示；顶部显示剩余时间，切换应用内页面后保持本次计时。运行中重新设置时明确是结束本次还是保留。

以下内容待确认，不默认纳入：

- 是否采用番茄钟及自动休息循环。
- 刷新、关闭标签页、再次登录时的恢复行为。
- 是否关联具体学习集，以及关联后如何切换课程。
- 是否将计时记入学习报告；计时时长只能表示计时行为，不能直接等同于实际专注或掌握程度。
- 到时提示采用站内视觉提示、声音或其他方式。

## 5. 空状态建议

- 无学习集：问候区下方以“创建第一个学习集”为主要行动；资料、笔记和测试区简洁说明内容会在此汇总。
- 已有学习集但无资料：引导进入相应学习集上传资料。
- 无笔记/测试：引导基于已有可用资料生成；资料选择及生成参数沿用对应模块。
- 无日历安排：正常显示日历和无安排状态。
- 无更新公告：显示真实空状态或折叠公告区，不放虚构发布记录。

## 6. 已明确的讨论结论

| 事项 | 用户结论 |
| --- | --- |
| 返回主页 | 保留课程导航 |
| 进入学习集列表 | 收起课程导航 |
| 主页学习集展示 | 突出最近使用的一个，旁边提供其他最近学习集及查看全部 |

## 7. 后续需要逐轮决定的事项

| 事项 | 建议，尚未确认 |
| --- | --- |
| 创建学习集 | 名称必填，简介、封面、考试日期等可选或稍后设置；入口提供在学习集列表与主页 |
| 进入学习集后的落点 | 第一次进入打开资料页，后续继续上次学习位置；未完成测试等状态需明确恢复方式 |
| 主页总览范围与跨课程跳转 | 所有学习集汇总；打开具体内容时显示其所属课程导航；全局列表只筛选时不切换当前课程 |
| 最近使用与卡片密度 | 以用户实际进入或使用学习集为依据，不因后台生成或公告更新改变最近课程；主卡旁的数量与各总览条数待定 |
| 刷新与登录恢复 | 页面刷新建议恢复导航状态与本次计时；关闭页面、退出登录与再次登录的规则单独明确 |
| 学习集列表管理 | 搜索、排序、重命名、归档、删除及影响提示的首期范围需确认；考试信息归属在此模块继续讨论 |
| 学习计时器 | 简单倒计时优先；课程关联、计时记录、报告统计、到时提示与番茄钟范围待定 |

头像进入个人中心后的页面关系、日历内容和公告维护方式也需后续细化，分别与 P08、P07 及公告功能衔接；不必在当前一轮一次决定全部细节。

软件公告与计时器是本轮新增范围。此阶段只确定产品位置与行为，尚未启动 UI 或业务代码实现。
